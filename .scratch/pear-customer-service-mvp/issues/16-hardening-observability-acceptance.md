# 16: 安全、可观测性与整体验收

**What to build:** 补齐限流、登录防暴力破解、日志隐私、健康检查、指标、非演示初始管理员、脱敏配置和完整文档；通过 REST＋SSE 主接缝跑通全部关键流程及故障回归，形成可交付 MVP。

**Blocked by:** 12: 退货验收与补发履约; 13: 支付异常人工处理; 14: 商品、库存与配送运营管理; 15: 知识资料运营与索引重建

**Status:** ready-for-agent

- [ ] 单实例内 AI 消息默认按用户或来源地址限制每分钟 20 条，登录连续失败 5 次后暂停该账号 15 分钟，上传单独限频且阈值可配置。
- [ ] 发往模型的内容经过字段最小化，日志默认不包含完整聊天、手机号、地址、令牌、密钥和私有图片地址。
- [ ] 健康检查、Prometheus 指标、请求关联 ID 和关键业务审计可用，健康与监控接口不会泄露敏感信息。
- [ ] 非演示环境没有固定默认密码，初始管理员通过一次性流程设置；演示账号和演示数据具有醒目标记。
- [ ] Docker Compose 可以启动 MySQL、Qdrant 和 MinIO，配置示例全部脱敏，真实密钥只由开发者自行注入。
- [ ] README、本地启动、架构、OpenAPI、演示流程、测试说明和两项 ADR 与最终实现一致，并包含 MySQL、Qdrant、MinIO 的备份注意事项。
- [ ] REST＋SSE 主测试接缝覆盖咨询、认证、加购、确认下单、支付、发货、三类售后、退款、补发、转人工和运营管理。
- [ ] 并发、幂等、越权、提示词注入、模型/Qdrant/MinIO 故障及重复通知回归通过，自动化测试不调用真实外部模型、支付或物流服务。
- [ ] 简易联调页面可以从游客咨询开始完成主要顾客流程，所有演示支付、物流和政策数据均明确标记。
- [ ] 未执行真实对外部署、制品发布、生产备份或恢复，交付说明清楚区分 MVP 与后续生产化事项。
