# 07: 两阶段确认下单与库存预占

**What to build:** 用户可以核对交易摘要并确认下单；系统重新校验商品、库存和配送条件，创建订单快照并预占库存，同时保证确认凭证绑定、防重复提交和库存竞争安全。

**Blocked by:** 06: 购物车、收货地址与配送试算

**Status:** ready-for-agent

- [ ] 下单准备阶段返回 SKU、数量、收货地址、商品金额、运费和应付总额，尚未创建订单或预占库存。
- [ ] 确认凭证有效期 5 分钟，并绑定当前用户、会话、操作类型和本次购买内容，过期或跨对象使用会被拒绝。
- [ ] 用户确认时重新校验上下架、价格、可售库存、配送范围和运费，任何变化都要求重新准备或明确提示。
- [ ] 创建待支付订单时原子预占库存，两名顾客竞争最后库存时只能有可行数量的订单成功。
- [ ] 订单保存商品、价格、收货地址和联系电话快照，后续商品或地址簿变化不会改写历史订单。
- [ ] 重复确认和网络重试不会创建重复订单或重复预占，成功后只移除本次购买的购物车商品行。
- [ ] SSE 区分待确认操作和业务执行结果，必要结果先持久化再发送。
- [ ] 接口及并发测试覆盖确认绑定、过期、业务变化、库存竞争、幂等和订单快照。
